YU Fluid 통합 CFD 웹앱 | 설치·실행 안내
===================================

먼저 ZIP을 완전히 압축 해제하세요. ZIP 안에서 파일을 직접 실행하거나 viewer,
data, src 폴더를 따로 옮기면 화면 또는 새 계산이 동작하지 않습니다.

[1] 저장된 결과만 보기 — 설치 불필요

압축 해제 폴더의 index.html을 브라우저로 여세요. Python, Docker, 인터넷,
백엔드 서버 없이 기존 849,284셀 결과·온도/수렴 그래프·CAD 도면·3D 메시를
볼 수 있습니다. viewer/mesh-volume-data.js를 포함한 viewer 폴더 전체를
같은 위치에 두어야 3D 전체 격자가 보입니다. 이 파일 화면에서는 발표를 위해
기준 CAD 결과 연결과 CAD→메시→S0→S1→S2→결과 뷰어 데모 흐름이 버튼으로
동작합니다. 데모 단계는 실제 형상 검증·파일 생성·OpenFOAM 계산을 수행하지
않고 저장된 3D 결과로 연결합니다. 실제 계산은 아래 로컬 서버에서 실행합니다.

[2] 새 CAD 계산까지 실행할 때 필요한 것

- macOS 또는 Windows PC의 Python 3.12 이상. 3.13·3.14도 허용하며
  3.12를 별도로 설치할 필요는 없습니다. 외부 패키지 설치 성공 여부는
  실행기의 pip 결과로 확인합니다.
- Docker Desktop 설치 및 실행. Docker Engine과 Docker Compose 명령이
  모두 동작해야 합니다. Windows에서는 Linux 컨테이너 모드가 필요합니다.
  호스트 PC에 OpenFOAM을 별도 설치할 필요는 없습니다.
- 첫 실행 시 Python 패키지 다운로드와 첫 새 계산 시 Docker 기본 이미지
  다운로드/빌드를 위한 인터넷 연결. Python 의존성은 실행기가 가상환경에
  PyYAML, CadQuery, NumPy, Matplotlib, VTK, Pillow 등을 설치합니다.
- 새 CFD 계산 시작 전 압축 해제 드라이브에 최소 55 GiB 여유공간.
  Docker Desktop의 이미지/컨테이너 저장공간도 별도로 충분해야 합니다.
  계산은 CPU·메모리를 많이 사용할 수 있으며, 배포받는 PC의 전체 계산
  완료 여부는 그 PC에서 별도로 검증해야 합니다.

설치 확인 명령(터미널 또는 PowerShell):

  macOS:   python3 --version
  Windows: py -3 --version
  공통:    docker --version
           docker compose version
           docker info

docker info에서 서버 정보가 표시되지 않으면 Docker Desktop을 먼저 켜고
엔진이 준비될 때까지 기다리세요. 명령을 찾지 못하면 Docker Desktop 설치와
명령 경로를 확인하세요. 브라우저와 실행기는 같은 PC에서 사용합니다.

[3] 로컬 서버 실행과 계산 흐름

macOS는 run_mac.command, Windows는 run_windows.cmd를 실행하세요.
실행기가 .venv 가상환경과 Python 의존성을 준비한 다음 로컬 웹앱 서버를
시작합니다. 실행기 창을 닫지 않은 상태에서 같은 PC의 브라우저로
http://127.0.0.1:8765/ 에 접속하세요. 127.0.0.1은 그 PC 자신을 뜻하므로
다른 PC에서 이 주소를 입력해도 이 서버에 접속하지 않습니다.

계산하기 → STEP 3개 첨부/역할 지정 → 운전조건·메시 등급 선택 →
CAD/입출구/설정값 확인 → 새 CFD 계산 시작 순서입니다. 계산 단계는
CAD 확인, 메시·품질, S0 냉간 유동, S1 정상 CHT, S2 과도 열해석,
검증·후처리입니다. 확인 팝업까지만 보여주려면 '새 CFD 계산 시작'을
누르지 마세요. 지원 형상은 현재 검증된 23셀 5–4–5–4–5 탱크 계열의
영역별 STEP 3개와 원형 상하 포트입니다. STL은 형식 확인용이며,
STL만으로 새 CFD 계산을 시작할 수 없습니다. 냉각수 종류도 현재 검증된
상수 물성 범위로 제한됩니다.

'기준 CAD 치수 변경'을 선택하면 STEP 파일을 따로 준비하지 않아도 됩니다.
탱크 X·Y·Z 또는 목표 외곽 체적, 입구 Ø, 출구 Ø를 입력하고 형상·조건을
확인한 뒤 'STEP/STL 생성'을 누르세요. CadQuery가 영역별 STEP/STL을 만들고
셀/벽/포트 간섭, 닫힌 냉각수 체적, 23개 배터리 고체, 입·출구 면적을
검사합니다. 생성 파일은 build/imported_runs/parametric/<생성 ID>/에
보존됩니다. 형상·운전조건 확인 후 새 CFD 계산을 명시적으로 시작하면
메시·S0·S1·S2·검증·결과 게시까지 이어집니다.

[4] 실제 계산 단계와 수렴 종료

전체 계산을 시작하면 CAD 검사 → 메시 생성·품질 검사 → S0 냉간 유동 →
S1 정상 CHT → S2 과도 열해석 → 검증·후처리 순서로 실행합니다. S0와
S1은 우선 6,000회 계산하고 최근 200회의 필수 raw initial residual이
1e-4 이하인지 질량·압력·온도·에너지 gate와 함께 판정합니다. 수렴 관련
gate만 실패하면 기존 장에서 500회씩 이어 계산하며 최대 9,500회입니다.

S2는 1초 간격으로 1,800초를 계산합니다. 매초 동적 발열을 갱신하고
유체·고체 에너지를 최대 200회 결합하되, 양쪽 모든 영역의 최신 h initial
residual이 1e-5 미만이면 그 초의 남은 내부 반복을 즉시 끝내고 다음 초로
갑니다. 물리 시간이나 발열 갱신 자체를 건너뛰는 기능은 아닙니다. 200회에도
미달하면 상한 도달로 기록하며 임의로 PASS 처리하지 않습니다. 마지막에는
잔차뿐 아니라 질량수지·에너지수지·온도장과 시간 표본의 완전성을 함께
검사하고, 모든 필수 보고서가 통과해야 결과 뷰어를 생성합니다.

[5] Docker 이미지: 미리 없어도 정상입니다

이 ZIP에는 Docker 이미지가 없습니다. 새 계산의 첫 Docker 단계에서
생성된 case/compose.yaml과 case/Dockerfile.openfoam을 사용해
opencfd/openfoam-default:2512 기본 이미지를 가져오고,
cfd-twin-openfoam-v2512-python3:local 이미지를 빌드합니다.
실행 명령은 docker compose run --rm --build 형식이므로 이미지가 없다는
사실만으로 오류는 아닙니다. 첫 빌드에는 시간이 걸릴 수 있습니다.
인터넷이 없거나 Docker 엔진이 꺼져 있으면 빌드에 실패하며,
이 경우 아래 worker.log의 구체적 오류를 확인하세요.

[6] 중지·오류 확인

- 'Failed to fetch' 또는 '상태 연결 끊김': 브라우저가 로컬 서버의 응답을
  받지 못한 상태입니다. Docker 이미지가 없다는 메시지와는 다릅니다.
  http://127.0.0.1:8765/api/status 가 열리는지 확인하고, 안 열리면
  실행기 창의 오류를 확인하세요. 서버를 재시작할 때는 기존 압축 해제
  폴더에서 실행하세요. 서버만 중지돼도 별도 CFD 작업은 계속될 수 있으므로
  계산이 중단됐다고 가정하거나 새 작업을 바로 시작하지 마세요.
- 'Docker daemon에 연결할 수 없음' 또는 이미지 다운로드 실패:
  Docker Desktop 실행 상태, docker info, 인터넷 연결을 확인하세요.
- '계산 중지'를 누른 후 브라우저 오류가 난 경우: 해당 작업 폴더의
  cancel.request가 있으면 중지 요청은 접수된 것입니다. status.json의
  상태가 cancelled인지 확인하세요. 파일이 없고 서버가 살아 있으면
  같은 작업 화면에서 중지를 다시 요청하세요.
- Python/CadQuery/VTK 설치 실패: 실행기 창의 pip 오류를 확인하세요.
  설치가 완료되지 않으면 새 CAD의 실제 형상 검사를 할 수 없습니다.
- 디스크 여유 부족: 기존 결과를 자동 삭제하지 않습니다. 최소 55 GiB를
  확보한 뒤 새 계산을 시작하세요.

새 계산의 기록은 build/imported_runs/runs/<작업 ID>/에 저장됩니다.
worker.log는 Docker·메시·솔버 오류, status.json은 현재 상태,
cancel.request는 중지 요청 접수 여부를 보여줍니다. 서버 실행기 창의
Python 오류와 worker.log를 함께 확인해야 원인을 구분할 수 있습니다.
기존 배포 결과의 검증 보고서는 data/case/에 있으며 원본 솔버 로그는
마지막 512 KiB만 동봉됩니다. 전체 41 GiB 계산 필드는 ZIP에 없습니다.

[7] 결과 사용 범위

저장된 적응형 결과는 단일 메시 검토용입니다. S2 1,800개 시간단계 중
32개는 목표 에너지 잔차에 도달하기 전에 결합 반복 상한에 닿았습니다.
원본 잔차·에너지 수지 데이터는 삭제하거나 PASS로 바꾸지 않았습니다.
격자 독립성·다른 해석기와의 교차검증 전에는 논문 최종 승인값으로
취급하지 마세요. 또한 현재 저장 결과는 수정 전 포트 CAD로 계산됐으므로,
새 포트 위치의 메시·S0·S1·S2 재계산 전에는 비교·UI 시연용입니다.
이전 기준선 3D 결과는 중복 포함하지 않았습니다.

[8] Git 체크아웃에서 새 실험

Python 3.12 이상에서 distribution/run_windows.cmd 또는
distribution/run_mac.command를 실행하세요. 기존 viewer/가 없어도
결과 0개 상태로 시작할 수 있습니다. 첫 검증된 계산이 결과 뷰어를 만들고
이후 결과를 누적합니다. configs/experiments/frame_fit_water.yaml과
tools/run_experiment.py로 이전 batch.json 없이 시안을 준비할 수 있습니다.
자세한 명령은 docs/windows_and_new_experiments.md를 확인하세요.
